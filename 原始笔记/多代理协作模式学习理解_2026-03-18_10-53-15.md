当前常见的多代理协作，可以抽象为两类主模式：
一种是子代理模式，拥有独立的上下文，可以独立的完成一些任务，而不需要与与其它子代理合作，主agent给分配任务在自己的独立上下文执行就可以。比如分析代码仓库，或者有100个相同的任务，主agent 给它分20个。
另一种就是Claude Code Agent teams 和 Qoder Experts模式，这种模型子agent要想并行工作，各个子agent的工作是有一定的相关性的，他们之间需要合作，一个子agent的工作与其它子agent的工作结果非常相关，需要了解其它子agent的工作结果现状，才知道自己该怎样干，下一步干什么，需要配合。所以，这种模式，各个子agent的上下文并非完全独立，它们一般是各自独立上下文 + 共享任务面板/消息/项目状态 + Team Lead 汇总协调。Team Lead分配任务，汇总当前工作，重新分配指导工作；子agent自己也可以读取共享任务面板、消息、项目状态，来计划自己的下一步工作。另外，Claude Code Agent teams 的各个子agent之间还可以互相通信，子agent需要了解其它子agent的工作信息，可以自己问。像一些强顺序、强耦合的工作，子代理的工作的相关性非常高的，反而不利于这种模式，沟通成本太高。所以Qoder Experts模式其实已经做了工作上的拆分，前端、后端、审查，选择了一个耦合程度没那么高的拆分方式。这种模式其实更像是多种主代理模式，窗口多开，主代理还可以有自己的子代理。
多代理模式主要的价值就是并行执行，节省时间，避免上下文污染。
