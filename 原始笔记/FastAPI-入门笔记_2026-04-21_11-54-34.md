# FastAPI 入门笔记

### 第一步：导入库

先导入 FastAPI 需要的库，以及你业务里需要的 Python 库。

常见导入：

```python
from fastapi import FastAPI, HTTPException
from fastapi.responses import FileResponse, HTMLResponse, JSONResponse
from pydantic import BaseModel
```

还可能导入普通 Python 库：

```python
import json
import uuid
from pathlib import Path
```

\---

## 2\. 第二步：实例化 app 对象

FastAPI 项目最核心的一步就是先创建一个应用对象：

```python
from fastapi import FastAPI

app = FastAPI()
```

这个 `app` 可以理解为整个后端应用的总入口。

后面的路由都是挂在这个对象上的，例如：

```python
@app.get("/")
def root():
    return {"message": "hello"}
```

所以可以记住一句话：

**先有 `app = FastAPI()`，后面才能挂载路由。**

\---

## 3\. 第三步：通过路由接收请求

FastAPI 主要是通过“路由 + 函数”来处理前端请求。

例如：

```python
@app.get("/projects")
def get\_projects():
    return \[]
```

这里的含义是：

* 当前端访问 `/projects`
* 并且请求方式是 `GET`
* 就执行下面这个 Python 函数

\---

## 4\. 常见请求方式

最常见的是：

* `GET`：读取数据
* `POST`：新建数据 / 提交数据
* `PUT`：整体更新数据
* `PATCH`：部分更新数据
* `DELETE`：删除数据

\---

## 5\. GET 和 POST 怎么理解

### 5.1 GET

`GET` 一般用于“获取数据”。

常见特点：

* 通常用来给前端返回数据
* 一般通过**路径参数**和**查询参数**接收信息
* 一般不使用 body 请求体

示例：

```python
@app.get("/projects/{pid}")
def get\_project(pid: int):
    return {"id": pid}
```

这里的 `pid` 就是路径参数，下面的函数可以作为参数导入直接就可以使用。

\---

### 5.2 POST

`POST` 一般用于“提交数据”或“创建数据”。

常见特点：

* 可以接收请求体 body
* 前端把 JSON 数据发给后端
* 后端处理后再返回结果

示例：

```python
from pydantic import BaseModel

class ProjectCreate(BaseModel):
    name: str

@app.post("/projects")
def add\_project(body: ProjectCreate):
    return {"name": body.name}
```

这里的 `body` 就是请求体对象，直接作为参数导入执行函数就可以了。

\---

## 6\. FastAPI 里三种最重要的参数来源

在路由函数里，后端接收到的数据主要来自三种地方：

1. 路径参数
2. 查询参数
3. 请求体 body

\---

## 7\. 路径参数（Path Parameter）

路径参数就是写在 URL 路径里的变量。

例如：

```python
@app.get("/projects/{pid}")
def get\_project(pid: int):
    return {"pid": pid}
```

访问地址：

```text
/projects/123
```

这时：

* 路径里的 `123`
* 会自动传给函数参数 `pid`

所以可以理解为：

**路径参数 = URL 路径中的动态部分**

\---

## 8\. 查询参数（Query Parameter）

这个是你目前最容易混淆的地方。

### 8.1 查询参数是什么

查询参数就是 URL 里 `?` 后面的那部分。

例如：

```text
/projects?page=1\&keyword=test
```

其中：

* `page=1`
* `keyword=test`

这两个就是查询参数。

\---

### 8.2 FastAPI 里怎么接收查询参数

你只需要把它写成函数参数即可：

```python
@app.get("/projects")
def get\_projects(page: int = 1, keyword: str = ""):
    return {
        "page": page,
        "keyword": keyword
    }
```

当前端访问：

```text
/projects?page=2\&keyword=python
```

FastAPI 会自动得到：

```python
page = 2
keyword = "python"
```

\---

### 8.3 查询参数一般用来干什么

查询参数最常见的用途不是“查数据库”这个动作本身，而是：

* 搜索
* 筛选
* 分页
* 排序
* 条件限制

比如：

#### 分页

```text
/projects?page=2\&page\_size=10
```

#### 搜索

```text
/projects?keyword=fastapi
```

#### 状态筛选

```text
/projects?status=done
```

#### 排序

```text
/projects?sort\_by=create\_time
```

所以你可以把查询参数理解为：

**查询参数 = 给“获取数据”这个动作附加条件**

\---

### 8.4 为什么叫 query

这里的 “query” 不是说 FastAPI 专门有一个叫 query 的语法必须要写。

它更多是在语义上表示：

* query parameter
* 查询参数

也就是 URL 里 `?` 后面的参数。

你完全可以不用显式写 `Query(...)`，直接这样写：

```python
@app.get("/projects")
def get\_projects(keyword: str = "", page: int = 1):
    ...
```

FastAPI 就已经会把它当作查询参数。

\---

### 8.5 什么时候会用 `Query(...)`

如果你只是简单接收查询参数，通常直接写默认值就够了。

如果你想补充：

* 默认值
* 最小值
* 最大值
* 说明文字

就可以使用 `Query(...)`：

```python
from fastapi import Query

@app.get("/projects")
def get\_projects(
    page: int = Query(1, ge=1, description="页码，最小为1"),
    keyword: str = Query("", description="搜索关键词")
):
    return {"page": page, "keyword": keyword}
```

这里：

* `ge=1` 表示大于等于 1
* `description` 会显示在自动文档里

所以你可以把它理解为：

**`Query(...)` 是“更精细地定义查询参数”，不是必须写。**

\---

## 9\. 请求体 body（Body）

body 一般是前端通过 JSON 发送给后端的数据。

例如前端发送：

```json
{
  "name": "测试"
}
```

后端这样接收：

```python
from pydantic import BaseModel

class ProjectCreate(BaseModel):
    name: str

@app.post("/projects")
def add\_project(body: ProjectCreate):
    return {"name": body.name}
```

这里：

* `ProjectCreate` 定义了 body 的结构
* `body` 是一个对象
* 可以通过 `body.name` 取值

\---

## 10\. 为什么请求体通常搭配 BaseModel

`BaseModel` 是 Pydantic 提供的模型基类。

作用是：

* 提前定义请求体的数据格式
* 自动做类型校验
* 自动提示缺失字段
* 自动生成接口文档

例如：

```python
class UserCreate(BaseModel):
    name: str
    age: int
```

如果前端传来的 JSON 不是这个结构，FastAPI 会自动报错。

所以你可以这样理解：

**`BaseModel` = 用来定义 body 的“标准格式”**

\---

## 11\. 路径参数、查询参数、body 在函数里怎么传入

FastAPI 很方便的一点是：

**这些参数都可以直接写到路由函数参数里。**

例如：

```python
from pydantic import BaseModel

class ProjectCreate(BaseModel):
    name: str

@app.post("/projects/{pid}")
def update\_project(pid: int, page: int = 1, body: ProjectCreate = None):
    return {
        "pid": pid,
        "page": page,
        "body\_name": body.name if body else None
    }
```

这里：

* `pid` → 路径参数
* `page` → 查询参数
* `body` → 请求体

虽然真实项目里不一定这样混着写，但这个例子能帮助理解三者的来源。

\---

## 12\. 第四步：返回数据

FastAPI 路由函数执行完以后，要把结果返回给前端。

常见返回类型有：

* `dict`
* `list`
* Pydantic 模型
* `FileResponse`
* `HTMLResponse`
* `JSONResponse`
* 用 `HTTPException` 返回错误

\---

## 13\. 常见返回方式

### 13.1 返回 dict

最常见：

```python
@app.get("/hello")
def hello():
    return {"message": "hello"}
```

FastAPI 会自动转成 JSON。

\---

### 13.2 返回 list

```python
@app.get("/projects")
def get\_projects():
    return \[
        {"id": 1, "name": "A"},
        {"id": 2, "name": "B"}
    ]
```

\---

### 13.3 返回 Pydantic 模型

```python
class ProjectOut(BaseModel):
    id: int
    name: str

@app.get("/project")
def get\_project():
    return ProjectOut(id=1, name="测试项目")
```

\---

### 13.4 返回文件 `FileResponse`

适合返回：

* HTML 文件
* 下载文件
* 静态文件

例如：

```python
from fastapi.responses import FileResponse

@app.get("/")
def index():
    return FileResponse("index.html", media\_type="text/html")
```

这表示访问 `/` 时，直接把 `index.html` 文件返回给浏览器。

\---

### 13.5 返回 HTMLResponse

如果你不是返回一个 HTML 文件，而是直接返回 HTML 字符串：

```python
from fastapi.responses import HTMLResponse

@app.get("/page")
def page():
    return HTMLResponse("<h1>你好</h1>")
```

\---

### 13.6 返回 JSONResponse

如果你想更明确地控制 JSON 响应：

```python
from fastapi.responses import JSONResponse

@app.get("/json")
def get\_json():
    return JSONResponse(content={"ok": True})
```

\---

### 13.7 使用 HTTPException 返回错误

当后端发现：

* 数据不存在
* 参数有问题
* 权限不对
* 文件不存在

可以抛出异常：

```python
from fastapi import HTTPException

@app.get("/projects/{pid}")
def get\_project(pid: int):
    if pid != 1:
        raise HTTPException(status\_code=404, detail="项目不存在")
    return {"id": pid}
```

这是一种标准写法。

你可以记住：

**正常情况用 `return`，异常情况用 `raise HTTPException(...)`**

例如：

```python
raise HTTPException(status\_code=404, detail="项目不存在")
```

这样前端就能识别出这是一个错误响应，而不是普通数据。

\---

## 14\. 路由地址怎么科学设置

路由地址建议按照“资源层级”来设计，而不是按动作命名。

推荐：

```text
/projects
/projects/{pid}
/projects/{pid}/commands
/projects/{pid}/commands/{cid}
```

这种写法体现的是：

* 有一个项目集合 `projects`
* 每个项目下面有命令集合 `commands`

例如：

```text
/projects/{pid}/commands
```

表示：

**某个项目下面的命令列表**

这是一种典型的层级关系写法。

\---

## 15\. 为什么不推荐把动作写进路径里

不太推荐这样：

```text
/getProjects
/addProject
/deleteProject
```

因为：

* 动作已经由 `GET / POST / DELETE` 表示了
* 路径更应该表示资源本身

所以更推荐：

* `GET /projects`
* `POST /projects`
* `DELETE /projects/{pid}`

\---

## 16\. 前端怎么访问 FastAPI 地址

前端最常见的方式就是用 `fetch()`。

例如，获取项目列表：

```javascript
fetch("/api/projects")
```

如果要发送 POST 请求：

```javascript
fetch("/api/projects", {
  method: "POST",
  headers: {"Content-Type": "application/json"},
  body: JSON.stringify({name: "测试"})
})
```

这段代码的含义是：

* 请求地址：`/api/projects`
* 请求方式：`POST`
* 请求头说明：发送的是 JSON
* 请求体内容：`{"name": "测试"}`

\---

## 17\. 前后端是怎么对应起来的

例如后端：

```python
class ProjectCreate(BaseModel):
    name: str

@app.post("/api/projects")
def add\_project(body: ProjectCreate):
    return {"name": body.name}
```

前端：

```javascript
fetch("/api/projects", {
  method: "POST",
  headers: {"Content-Type": "application/json"},
  body: JSON.stringify({name: "测试"})
})
```

这里对应关系是：

* 前端发到 `/api/projects`
* 后端刚好有 `@app.post("/api/projects")`
* 前端 body 里有 `name`
* 后端 `ProjectCreate` 也要求有 `name`

只要这两个结构对上，就能正确传值。

## 18\. 一个最小可运行的完整示例

### 18.1 后端 `main.py`

```python
from fastapi import FastAPI, HTTPException, Query
from fastapi.responses import FileResponse
from pydantic import BaseModel

app = FastAPI()

projects = \[
    {"id": 1, "name": "项目A"},
    {"id": 2, "name": "项目B"},
]

class ProjectCreate(BaseModel):
    name: str

@app.get("/")
def index():
    return FileResponse("index.html", media\_type="text/html")

@app.get("/api/projects")
def get\_projects(
    page: int = Query(1, ge=1, description="页码"),
    keyword: str = Query("", description="关键词")
):
    result = \[p for p in projects if keyword in p\["name"]]
    return {
        "page": page,
        "keyword": keyword,
        "items": result
    }

@app.get("/api/projects/{pid}")
def get\_project(pid: int):
    for p in projects:
        if p\["id"] == pid:
            return p
    raise HTTPException(status\_code=404, detail="项目不存在")

@app.post("/api/projects")
def add\_project(body: ProjectCreate):
    new\_project = {
        "id": len(projects) + 1,
        "name": body.name
    }
    projects.append(new\_project)
    return new\_project
```

## 19\. 我目前可以先记住的核心口诀

### 19.1 开发流程口诀

1. 导入库
2. `app = FastAPI()`
3. 写路由
4. 接收参数
5. 返回结果

\---

### 19.2 参数来源口诀

* 路径里的是：路径参数
* `?` 后面的是：查询参数
* JSON 里的是：body 请求体

\---

### 19.3 请求方式口诀

* `GET`：取数据
* `POST`：提交/创建
* `PUT`：整体更新
* `DELETE`：删除

\---

### 19.4 返回值口诀

* 正常：`return`
* 报错：`raise HTTPException(...)`

\---

## 20\. 我对 FastAPI 当前阶段的总结

目前可以先把 FastAPI 粗略理解成：

**用 Python 函数来定义接口；  
用 `app = FastAPI()` 创建应用；  
用 `@app.get()` / `@app.post()` 等装饰器挂载路由；  
用路径参数、查询参数、请求体接收前端数据；  
用 `return` 返回正常结果，用 `HTTPException` 返回错误。**
