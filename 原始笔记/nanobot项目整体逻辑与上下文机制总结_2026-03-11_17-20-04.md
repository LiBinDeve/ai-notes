# nanobot 学习总结（原始记录）

我的总结就是，nanobot 项目的整体逻辑是从 `onboard` 函数进行初始化：

- 在本地创建若干记忆文件和 `config` 文件。
- 在 `config` 文件中配置模型提供商、模型、API Key、baseurl，以及远程连接 channel 的 URL 和 API Key。

然后从 `gateway` 函数开始启动：

- `gateway` 会读取 `config` 获取模型配置，实例化 `agentloop`。
- 会把实例化的 agent 传递给 cron 的回调函数用于处理 cron 任务。
- cron 任务中给 agent 的提示词就是任务 job 说明。
- cron 回调函数还会把 agent 返回的回复送入 `outbusmessage`。

同时，`gateway` 也会把实例化的 agent 传递给 heartbeat 的回调函数：

- heartbeat 回调接收的提示词不是任务说明，而是让其读取 `heartbeat.md` 文件，从文件里自己找需要定时执行的任务。
- heartbeat 任务在 agent 循环内执行完后不会进入 `outbusmessage`，只会打印一条日志：heartbeat 任务执行完成。

`gateway` 还会实例化 `bus`、`channel` 对象：

- 同一个 `bus` 对象会传递给 `channel`，用于收集各个渠道的入站消息。
- 同时也会传递给 `agentloop` 对象，`agent.run` 执行时会调用该对象存入出站消息。
- cron 回调函数也会调用 `bus` 对象存入出站消息。
- 同时这个bus对象也会传递给channel用于手机入站消息。 `channel.all_start` 之后会启动各渠道的 `start`，开始监听各渠道消息并存入进站消息队列。

关于上下文记忆：

- 项目在 `onboard` 时会创建很多 `.md` 文件。
- 但是提示词里只有 `memory.md` 路径，并提示在需要时主动写入这个文件。
- 其它 `.md` 文件都需要主动提示 agent 循环去写入，或者手动写入。

整个上下文包含：

- 这些 `.md` 记忆文件。
- 历史对话。
- `always=true` 的技能。
- 其它技能摘要。
- 图片经base64编码后和用户消息一块进入上下文。cli模式下文件只能通过粘贴路径，让agent利用读文件工具读取后，作为工具结果返回。

子agent:
- 子agent的创建是agent循环通过spawn工具发布一个任务给子agent去执行，子agent会给这轮主agent循环返回的工具结果是子agent已经启动的消息。子agent这轮循环返给用户的回复是自己开启了几个子agent。
- 也就是说子agent不是即时反馈的，子agent的执行结果不在本轮agent循环内返回，而是把执行结果写入入站消息，下一次agent从入站消息消费消息的时候会重开一个循环去处理子agent返回的结果。
