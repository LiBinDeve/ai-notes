# 一、本地仓库与分支操作

\---

## 1\. 环境检查与 Git 配置

说明：查看当前 Git 是否已经安装并确认版本号。

```powershell
git --version
```

说明：设置 Git 的全局用户名，用于后续提交记录的作者信息。

```powershell
git config --global user.name "Li Bin"
```

说明：设置 Git 的全局邮箱，用于后续提交记录的作者邮箱。

```powershell
git config --global user.email "YoungAhBin@outlook.com"
```

说明：查看当前 Git 的完整配置，确认用户名、邮箱等设置是否生效。

```powershell
git config --list
```

\---

## 2\. 创建项目目录并初始化仓库

说明：在桌面上新建一个名为 `git-test` 的项目文件夹。

```powershell
mkdir git-test
```

说明：进入刚创建的 `git-test` 目录，后续 Git 操作都在这里进行。

```powershell
cd git-test
```

说明：把当前目录初始化为一个新的 Git 仓库。

```powershell
git init
```

\---

## 3\. 查看仓库当前状态

说明：查看当前仓库有哪些分支。

```powershell
git branch
```

说明：查看当前工作区和暂存区的状态，比如有没有文件变更、是否已暂存。

```powershell
git status
```

\---

## 4\. 创建文件并提交第一个版本

说明：用记事本打开并创建 `hello.py` 文件。

```powershell
notepad hello.py
```

说明：把 `hello.py` 加入暂存区，为提交做准备。

```powershell
git add hello.py
```

说明：提交第一次版本，形成仓库中的第一个 commit。

```powershell
git commit -m "feat: first commit"
```

说明：查看提交历史，确认第一次提交已经写入仓库。

```powershell
git log
```

\---

## 5\. 创建功能分支并在分支上开发

说明：基于当前分支新建并切换到 `feature/greet` 功能分支。

```powershell
git switch -c feature/greet
```

说明：把修改后的 `hello.py` 再次加入暂存区。

```powershell
git add hello.py
```

说明：在 `feature/greet` 分支上提交本次功能修改。

```powershell
git commit -m "feat: greet from feature branch"
```

\---

## 6\. 切回主分支并继续开发

说明：切换回 `master` 主分支。

```powershell
git switch master
```

说明：把主分支中的文件修改加入暂存区。

```powershell
git add hello.py
```

说明：在主分支提交本次修改。

```powershell
git commit -m "feat: greet from main branch"
```

说明：切换到 `feature/greet` 分支查看该分支的提交情况。

```powershell
git switch feature/greet
```

说明：再次切回 `master`，为后续合并分支做准备。

```powershell
git switch master
```

\---

## 7\. 合并分支并处理冲突

说明：把 `feature/greet` 分支合并到当前主分支；这次合并触发了冲突，需要手动解决。

```powershell
git merge feature/greet
```

说明：冲突解决后，把修复后的 `hello.py` 重新加入暂存区。

```powershell
git add hello.py
```

说明：提交一次合并提交，保存冲突解决后的最终结果。

```powershell
git commit -m "merge: feature/greet into main (resolve conflict)"
```

处理冲突：就是文件内会把不同分支的提交共同作用的代码都放在文件内，手动在文件内删除不要的，留下自己选择的。并删除冲突的符号，然后重新增加提交。

\---

## 8\. 打标签并查看更清晰的历史

说明：给当前版本打一个带说明的标签 `v0.1.0`。

```powershell
git tag -a v0.1.0 -m "first runnable demo"
```

说明：查看当前仓库里的所有标签。

```powershell
git tag
```

说明：查看标签 `v0.1.0` 对应的commit的详细信息。

```powershell
git show v0.1.0
```

说明：用单行、带分支装饰、图形化的方式查看整个提交历史。

```powershell
git log --oneline --decorate --graph --all
```

说明：查看当前 `HEAD` 指向提交的详细内容。 `HEAD` 就代表当前分支最新的提交的指针。

```powershell
git show HEAD
```

\---

## 9\. 制造错误提交后再撤销

说明：把当前修改加入暂存区，准备提交一次新的改动。

```powershell
git add hello.py
```

说明：提交一次错误改动，用来演示后续如何撤销提交。

```powershell
git commit -m "oops: bad change"
```

说明：撤销最新一次提交，并自动生成一个新的“反向提交”来恢复内容。

```powershell
git revert HEAD
```

说明：再次查看日志，确认错误提交已经被 revert。

```powershell
git log
```

撤销提交后会进入vim编辑器。需按esc，不管有没有变化，直接输入"qa!"，然后回车就会退出。

\---

## 10. 一句话总结这份日志的操作链路

这份日志完整演示了：**配置 Git → 初始化仓库 → 首次提交 → 新建分支开发 → 回主分支开发 → 合并并解决冲突 → 打标签 → 查看历史 → 用 `git revert` 撤销错误提交**。



# 二、远程仓库操作与常见问题

\---

## 11\. 远程仓库操作（已验证有效流程）

说明：添加远程仓库地址，并命名为 origin（origin 只是一个别名）。

```bash
git remote add origin https://github.com/YoungAhBin/computer-use.git
```

说明：查看远程仓库地址是否配置成功。

```bash
git remote -v
```

说明：把当前分支重命名为 main（与远程默认分支保持一致）。本地默认分支名是master，不改的话，推拉之后，远程就会多个分支master

```bash
git branch -M main
```

说明：当远程仓库已有内容时，先拉取远程代码并允许合并不同历史。

```bash
git pull origin main --allow-unrelated-histories
```

说明：把本地代码推送到远程仓库，并建立跟踪关系（第一次必须带 -u）。

```bash
git push -u origin main
```

\---

## 远程操作核心理解（重点）

* origin 不是仓库地址，而是远程仓库的“别名”
* 一个本地仓库可以连接多个远程（origin / upstream），不同的仓库
* 第一次 push/pull 必须写 origin，是为了指定远程
* 使用 -u 后，会建立 tracking 关系

后续可以直接：

```bash
git push
git pull
```

无需再写 origin main

\---

## 常见错误总结

❌ 错误：直接 push 被拒绝  
原因：远程已有提交，本地没有同步

✅ 正确流程：

1. 先 pull
2. 再 push
